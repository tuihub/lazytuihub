# MVP game library and metadata providers

English | [中文](2026-11-23-mvp-games.zh.md)

## Concepts carried over

Gebura in librarian distinguishes personal games, source metadata and store listings. It also records categories and playtime. The waiter client distinguishes games, installations on a device and launch configurations, with directory scanning, metadata lookup and runtime tracking. This increment introduces the library and provider lookups. Device installations, launchers, scanning, automatic playtime tracking, private platform accounts, owned-library sync and desktop interaction remain open for discussion. ## Library entries, sources and links

The `games` plugin stores an account's games with stable IDs, editable titles, categories and per-device play sessions. A user can maintain a library with every provider disabled. Steam, Bangumi and VNDB ship as independently switchable plugins. Each registers title search and lookup by source ID. Online search returns the provider's first page of candidates. Imported metadata retains the provider's original ID. Entries and their source snapshots remain readable when a provider is missing. [Plugin boundaries](2026-11-17-mvp-plugins.en.md)

The import workflow looks up metadata and routes the write to the owner of the primary workspace. A lookup can run on another instance offering the provider. Specifying a target game confirms a link. A game can collect multiple sources, and one source record can describe multiple games. Without a target, import creates a game on first use or refreshes the sole existing link. Multiple linked games require an explicit target. Refresh preserves the user's title, categories and sessions. The library writes the source snapshot and its framework `describes` relationship in one transaction. Library access follows the account and game resource URIs. [Accounts and resource access](2026-11-19-mvp-account-identity.en.md)

## How the three data repositories fit

| Source | Input | Use in the MVP |
| - | - | - |
| [tuihub/bangumi-db](https://github.com/tuihub/bangumi-db) | PostgreSQL table `public.subject` | The [export query](../../src/LazyTuiHub.Bangumi/export-games.sql) selects games with their original and Chinese titles, summaries and dates. |
| [tuihub/vndb-db](https://github.com/tuihub/vndb-db) | VNDB database table `vn_titles` | The [export query](../../src/LazyTuiHub.Vndb/export-games.sql) selects one title per VN ID, preferring Japanese, then English, and includes its Latin transliteration. Online lookup also supplies details such as descriptions, images and developers. |
| [tuihub/tuihub-datasets](https://github.com/tuihub/tuihub-datasets) | Published [vndb_id_connector.json](https://datasets.tuihub.org/vndb_id_connector.json) and [game_id_list.json](https://datasets.tuihub.org/game_id_list.json) | `games matches` returns all rows matching a provider and original ID, preserving aliases, competing candidates and multiple IDs within a row. Users choose which links to import. |

Each provider queries its public service by default. Steam defaults to the US store in English. An instance can select a different region and language through `Games:steam:Country` and `Games:steam:Language`. Steam details retain the listing type, which distinguishes base games, demos and DLC. [Steam Store lookup example](https://store.steampowered.com/api/appdetails?appids=620) · [Bangumi API](https://github.com/bangumi/api) · [VNDB API](https://api.vndb.org/kana)

An instance can point an individual provider at a local JSONL snapshot. Run either PostgreSQL export query with `psql -XAt -v ON_ERROR_STOP=1 -f` to produce a snapshot. Providers read it line by line, using exact IDs for lookup and titles or alternative titles for search. The CLI reads the supplied cross-reference file on demand. Looking up a match leaves the library untouched. The operator controls when to refresh these files.

## Running the example

```sh
mise run run -- --command games --action add --title "My CLANNAD"
mise run run -- --command bangumi --action search --query CLANNAD
mise run run -- --command bangumi --action import --source-id 13 --game GAME_ID
mise run run -- --command games --action matches --dataset ./game_id_list.json --provider bangumi --source-id 13
mise run run -- --command vndb --action lookup --source-id v4 --Games:vndb:Snapshot ./vndb.jsonl
mise run run -- --command games --action show --game GAME_ID
```

Use the ID from the first command in place of `GAME_ID`. The commands share the default local workspace. Pass `--database PATH` to choose a different one.
