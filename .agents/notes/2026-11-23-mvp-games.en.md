# MVP game library and metadata providers

English | [中文](2026-11-23-mvp-games.zh.md)

## Library identity and evidence

The Games plugin gives each personal library entry a stable, account-scoped ID. Titles, categories and device play sessions belong to the user. Each online account and each scanned library reports its own observations. Steam ownership, Bangumi collection status, VNDB labels and an installation path can describe the same game. They answer different questions and retain their sources. This carries forward Gebura's separation of games and store records and waiter's device installations. [librarian game models](https://github.com/tuihub/librarian/blob/1fcb0f342a9d35134139707446e426dd2972bb03/internal/model/modelgebura/modelgebura.go) · [waiter game repository](https://github.com/tuihub/waiter/blob/ae1ae6f349eef99a8a300ed9276c319683ef5797/lib/repo/gebura_repo.dart)

An existing assignment takes precedence when the same observation reappears. Otherwise an exact provider ID or an unambiguous cross-reference can identify one personal game. The matcher checks both directions, including the number of IDs per provider and competing rows in the dataset. If the evidence points to multiple games, the library keeps the new entry separate. Titles support discovery. Users can move an observation, link several listings to one game or use one store bundle as metadata for several games. [TuiHub ID dataset](https://datasets.tuihub.org/game_id_list.json)

## Public catalogs and personal metadata

Games registers `IGameCatalog` implementations for search and lookup. Steam resolves its HTTP client for the Steam catalog. Bangumi and VNDB register SQLite catalogs. The provider commands and the library’s curation operations call the same typed workflows. Import succeeds when the workflow returns exactly one `GameEntry`. A workflow that completes without one reports a failure to both callers.

Bangumi and VNDB read their upstream SQLite catalogs in read-only mode. Three-character and longer searches use the upstream trigram title index. Shorter searches use substring matching. Bangumi filters subjects by game type. VNDB reads original-language titles, translations, release dates, artwork IDs and credited producers. [Bangumi SQLite PR](https://github.com/tuihub/bangumi-db/pull/1) · [VNDB SQLite PR](https://github.com/tuihub/vndb-db/pull/1)

Steam searches the store using the configured country and language and retains the listing type. The Steam plugin checks the storefront’s robots.txt for LazyTuiHub before online catalog requests. It honors path restrictions and upstream rate limits. A Steam JSONL snapshot can supply a local store fixture. [Steam storefront robots.txt](https://store.steampowered.com/robots.txt)

The catalogs are replaceable files shared across accounts. Importing an identified record routes its snapshot to the primary workspace through the provider workflow. The snapshot and its framework relationship commit together. The Games plugin can still display both when the provider is disabled or its catalog is offline. The desktop displays the source of each field. An explicit personal value takes precedence, followed by the first populated linked source ordered by provider and source ID. Refreshing a source preserves personal edits. Removing a source removes the corresponding relationship. Users can fill missing sources in one operation using installed catalogs and unambiguous IDs, or search a specific catalog and confirm individual matches.

## Binding and synchronization

Provider accounts belong to the signed-in LazyTuiHub account. The bindings use the platform's stable account ID, which permits several accounts at one provider. Games checks the account's connections URI for binding and synchronization and the library URI for inventory changes. Public metadata workflows carry source IDs. The local account adapter handles platform credentials. The host protects stored tokens with ASP.NET Core Data Protection scoped to the account, provider and platform ID. The existing key ring lives in the workspace's sibling `keys/` directory. Protect and back up that directory together with the workspace. [Account and resource access](2026-11-19-mvp-account-identity.en.md)

| Provider | Proof of account | Read-only synchronization |
| - | - | - |
| Steam | System browser, Steam OpenID 2.0 and a one-use loopback return address. The host verifies the assertion directly with Steam. | A host Web API key calls GetOwnedGames. Steam must disclose the game details to that key. An undisclosed library preserves the previous snapshot. |
| Bangumi | The personal access token identifies the account through `/v0/me`. | Check the stable ID on each sync and page through collections using the current username. Bangumi requires the username once one is set. Preserve each game’s collection status. |
| VNDB | Validate the personal token with `/authinfo` and check `listread` before binding. | Recheck the account and permission, then read its list and labels by VN ID through the final page. |

The provider finishes fetching before the library reconciles the observations in a single SQLite transaction. Cancellation, a failed page and a stale binding revision leave the previous snapshot available. A successful full refresh can mark observations absent. The personal game, local installations, linked snapshots and edits survive. Disconnecting clears the credential and retains the last successful observations with a disconnected status. Disabling a provider preserves the account's stored data. [Steam authentication](https://partner.steamgames.com/doc/features/auth) · [Bangumi API](https://github.com/bangumi/api) · [VNDB Kana](https://api.vndb.org/kana)

## Browsing and maintaining the library

Games opens on a full-width poster shelf with an optional compact list. Cards keep their titles visible and reserve the same space for missing or unavailable artwork. Search matches titles and aliases. Filters include installed, online, needs match, category and metadata source. Selecting a game opens its details alongside the shelf on wide screens or on a separate screen at smaller widths. Returning preserves filters and restores focus when the game still appears in the results. Whole-card targets with hover and keyboard feedback, prefilled edit forms and a folder picker next to the path field follow details from the reviewed waiter interface. The organization reflects a personal collection across sources, with titles and primary actions accessible by touch. [waiter library overview](https://github.com/tuihub/waiter/blob/ae1ae6f349eef99a8a300ed9276c319683ef5797/lib/view/pages/gebura/gebura_library_overview.dart) · [waiter editing form](https://github.com/tuihub/waiter/blob/ae1ae6f349eef99a8a300ed9276c319683ef5797/lib/view/pages/gebura/gebura_library_detail_app_panel.dart)

The page commands stay anchored when the inspector opens. A wide workspace divides below the toolbar. A narrow workspace shows one screen and restores the selected game, keyboard focus and scroll position on return. Category and metadata-source filters open in an anchored flyout. The scope control reserves the width of its selected state. Notifications float outside the grid layout.

Typography follows named roles with explicit line heights in each design. The poster keeps a 2:3 ratio. The grid reserves room for two title lines and one metadata line. Fluent and Material align metadata across each row. In the Mac appearance the caption follows the last visible title line, as in the native reference shelf. A one-line title places its caption one 16-point line higher than a two-line title. The project chooses the column density, spacing and inspector width. Keyboard focus has one outline independent of persistent selection. Material uses tonal surfaces, macOS uses a segmented control and Fluent uses an accent underline. Panel entrances fade and translate on the rendering clock. The duration is 167 ms for Fluent, 200 ms for macOS and 250 ms for Material. The application preference and the macOS or Windows system motion setting can suppress these transitions. On November 25, Argon accepted the three game-library appearances after inspecting the actual screens, keyboard focus, motion frames and macOS Retina rendering. In a 390-unit window the first row of two covers starts at 165 units in Fluent, 157 in macOS and 185 in Material. Opening the filter flyout moves the shelf by zero units. Opening the inspector keeps the page commands stationary. In that review all 13 sample titles shared a metadata baseline within their respective rows. The native rendering evidence comes from macOS. Hands-on review subsequently caught two Fluent regressions. The card now owns its button theme, with the outer frame painting hover, selection and keyboard focus. Its previous hover envelopes differed by 7 px on each edge. Both measured 158 × 296 px after the correction on macOS Skia at 1×. The inline action label uses the Fluent 20-unit line height and centers the text line beside the plus. The text ink moved from 2.5–3 DIP above the icon to 0–0.5 DIP below its center. The Microsoft Fluent Web specimen on this host measured 1–1.5 DIP below in light mode and 0.5–1 DIP below in dark mode. Product tests exercise both regressions and the [UI self-review standard](../../docs/development/desktop-ui-review.en.md) describes reproducing the measurements.

Details lead with the work, followed by installations grouped separately from online collections. Metadata provenance and play sessions expand on demand. **Identify** supports catalog search, linking, refreshing and unlinking. **Edit info** saves the title, categories and changed fields together, including a return to source values. **Reassign** moves one installation or collection observation to an existing game or creates a separate game for it.

**Sources** groups accounts, sync state and available actions by platform and lists local folders separately. The Steam scanner follows libraryfolders.vdf and installed app manifests. The generic folder scanner records immediate subdirectories. Device and path distinguish installations. The host CLI exposes the corresponding operations. A remote management API, launching games and automatic playtime tracking remain open.

Set `Games__bangumi__Database` and `Games__vndb__Database` to the decompressed SQLite paths. Their default location is `LazyTuiHub/catalogs/{provider}.sqlite` under local application data. Set `Games__IdDataset` to the downloaded game_id_list.json and `Games__steam__WebApiKey` for Steam library sync. The upstream PRs include local build instructions and a manual workflow to publish checksummed compressed assets after merge.

```sh
mise run run:desktop
mise run run -- --command games --action scan --scanner steam --root /path/to/SteamLibrary
mise run run -- --command games --action shelf
mise run run -- --command games --action fill --game GAME_ID
mise run run -- --command games --action show --game GAME_ID
```

Validation used real upstream dumps containing 119,444 Bangumi games and 68,340 VNDB works. The dataset connects Steam 324160, Bangumi 13 and VNDB v4. Scanning a CLANNAD manifest and filling from the two catalogs produced one entry with Bangumi's release date and VNDB's cover and developer. Account synchronization tests use protocol fixtures, including Steam OpenID verification, incomplete pagination and privacy-restricted responses.
