# CLI frontend and Windows 7 compatibility

English | [中文](2026-11-23-mvp-win7-cli.zh.md)

## Frontend boundaries

The host starts the local CLI with `--cli` and the desktop with `--desktop`. The local reader resolves the article and feed APIs in process. Workspace, game, and plugin commands run against local application services under the existing account policy. The standalone CLI uses the generated clients with an HTTPS endpoint. It can authenticate a user, select a shared account, manage feeds, list and get articles, mark an article read and revoke the session. Its deployment includes the API types and HTTP clients. SQLite, the HTTP server, business plugins and Avalonia belong to the host deployment.

Run `mise run run:cli -- --command articles --action list` for local reading. Supply `--endpoint https://SERVER` to use a remote server. Use `--command access --action login --username USER` to obtain a session token, then set `Access__Session` for subsequent commands. The client retains normal certificate, revocation and authorization checks.

## Guest and method

The reference guest is the English Microsoft Windows 7 Enterprise N SP1 x64 Evaluation release, build 7601.17514, with the i440FX machine, IDE disk and e1000 network adapter in QEMU. The unattended answer file installs only onto a newly created virtual disk. After setup, a startup task runs the test from its attached read-only CD and reports through the emulated serial port. Every functional test boots a new qcow2 overlay. Guest trust-store changes, package installations and test data are confined to that overlay.

The remote probe uses a real primary, a disposable account and an RSS fixture. It logs in over HTTPS, lists, creates, refreshes and reads a feed, lists articles by source, gets an article, marks it read and logs out. The local probe starts the host, loads the game DLL, writes to SQLite, then starts a second process and reads the same game. The [Win7 lab](../../tests/win7/) runs the remote probe for each deployment and the local probe for the JIT host.

## Deployment and functional results

Both deployments target the [repository LTS baseline](2026-11-24-dotnet-lts.en.md). QEMU runs the x64 guest on Apple Silicon. The test primary uses the same application runtime, with TLS, revocation and account checks enabled.

| Deployment | Windows 7 SP1 x64 environment | Verified operations |
| --- | --- | --- |
| Standalone Native AOT CLI | Original SP1, disposable test CA | Remote subscription and article operations, including login and logout |
| Self-contained JIT CLI and local host | SP1 with KB3063858, KB2999226 and the VC++ 2015–2019 x64 redistributable | Remote operations, cold loading of the game DLL, SQLite write and read after process restart |

The original SP1 loader could not start the ordinary self-contained JIT executable. The prerequisite packages were tested together. For a machine that only needs a remote reader, the Native AOT deployment ships one executable. It links YY-Thunks 1.2.3 and Microsoft's static Universal CRT at build time. The macOS build uses Microsoft's Native AOT compiler and Windows SDK/CRT libraries with LLVM's `lld-link`. Cross-OS Native AOT builds are outside Microsoft's supported build matrix. [YY-Thunks](https://github.com/Chuyu-Team/YY-Thunks) · [xwin](https://github.com/Jake-Shadle/xwin) · [Microsoft cross-compilation guidance](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/cross-compile)

The API generator supplies concrete Protobuf JSON converters and the CLI uses source-generated metadata for its login output. NSwag and Google.Protobuf still report trimming and AOT warnings. Repeat the guest probe after changing runtime or library versions, native linking, or the API shapes in use. Keep the local host on JIT for cold-start managed DLL loading. Windows 7 falls outside Microsoft's support matrix. Desktop windows, the HTTP listener, distributed jobs and online game providers have not been tested on this guest. [Native AOT limitations](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/#limitations-of-native-aot-deployment) · [Microsoft platform matrix](https://learn.microsoft.com/en-us/dotnet/core/install/windows#supported-versions)

## Reproduction

Install QEMU, xorriso and OpenSSL on the developer machine. The [archived copy of the Microsoft evaluation disc](https://archive.org/details/Win7EntNEvalSP1) has SHA-256 `f3d9fbd1a0ce17ad6f9009f14155c392db131bb1b324a4da5e97e269b2b6a123`.

```sh
mise run test:win7 install /path/to/windows7-sp1-x64.iso
mise run test:win7:publish
mise exec -- node tests/win7/fixture.mjs
```

To run the self-contained JIT package on a fresh SP1 install, place x64 [KB3063858](https://download.microsoft.com/download/0/8/e/08e0386b-f6af-4651-8d1b-c0a95d2731f0/Windows6.1-KB3063858-x64.msu), [KB2999226](https://support.microsoft.com/help/2999226) and [VC++ 2015–2019](https://aka.ms/vs/16/release/vc_redist.x64.exe) in `artifacts/win7/jit/updates/` under the names `loader.msu`, `ucrt.msu` and `vc_redist.x64.exe`. The guest installs them and reboots. The three packages were evaluated together. Their individual necessity has not been established.

Leave the temporary primary running and execute `mise run test:win7 run artifacts/win7/jit` in another terminal. The serial log contains `LTH-TEST-PASS` on success and is also saved as `artifacts/win7/jit-result.txt`. Restarting the fixture provisions a new account, certificate chain and workspace.

For the standalone AOT build on macOS, install xwin and LLVM lld and make `lld-link` available on PATH. After reviewing the Microsoft SDK license, prepare the SDK and start the same fixture.

```sh
xwin --accept-license --arch x86_64 --cache-dir artifacts/win7/xwin-cache splat --preserve-ms-arch-notation --disable-symlinks --output artifacts/win7/windows-sdk
mise run test:win7:publish:aot
mise exec -- dotnet build src/LazyTuiHub -c Release
mise exec -- node tests/win7/fixture.mjs artifacts/win7/aot
```

In a second terminal, run `mise run test:win7 run artifacts/win7/aot` against the original SP1 baseline. The executable is `artifacts/win7/aot/cli/LazyTuiHub.Cli.exe` and the guest serial log is `artifacts/win7/aot-result.txt`.
