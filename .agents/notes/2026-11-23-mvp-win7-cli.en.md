# CLI frontend and Windows 7 compatibility

English | [中文](2026-11-23-mvp-win7-cli.zh.md)

## Frontend boundaries

The host starts the local CLI with `--cli` and the desktop with `--desktop`. The local reader resolves the article and feed APIs in process. Workspace, game, and plugin commands run against local application services under the existing account policy. The standalone CLI uses the generated clients with an HTTPS endpoint. It can authenticate a user, select a shared account, manage feeds, list and get articles, mark an article read and revoke the session. Its deployment includes the API types and HTTP clients. SQLite, the HTTP server, business plugins and Avalonia belong to the host deployment.

Run `mise run run:cli -- --command articles --action list` for local reading. Supply `--endpoint https://SERVER` to use a remote server. Use `--command access --action login --username USER` to obtain a session token, then set `Access__Session` for subsequent commands. The client retains normal certificate, revocation and authorization checks.

## Guest and method

The reference guest is the English Microsoft Windows 7 Enterprise N SP1 x64 Evaluation release, build 7601.17514, with the i440FX machine, IDE disk and e1000 network adapter in QEMU. The unattended answer file installs only onto a newly created virtual disk. After setup, a startup task runs the test from its attached read-only CD and reports through the emulated serial port. Every functional test boots a new qcow2 overlay. Guest trust-store changes, package installations and test data are confined to that overlay.

The remote probe uses a real primary, a disposable account and an RSS fixture. It logs in over HTTPS, lists, creates, refreshes and reads a feed, lists articles by source, gets an article, marks it read and logs out. The local probe starts the host, loads the game DLL, writes to SQLite, then starts a second process and reads the same game. The [Win7 lab](../../tests/win7/) mounts the production host and CLI from the win-x64 release alongside the disposable fixture.

## Supported release and verified behavior

The [product release](../../docs/development/release.en.md) supplies the ordinary self-contained Windows x64 JIT host and CLI. The original Win7 SP1 loader cannot start these packages. On SP1 with KB3063858, KB2999226 and the VC++ 2015–2019 x64 redistributable, the CLI completed the remote reader scenario and the host loaded the game plugin, wrote SQLite and read back the data after restart. The tests installed these prerequisites together. Desktop windows, serving HTTP, distributed tasks and online game providers remain unverified on Win7. [Microsoft's supported Windows versions](https://learn.microsoft.com/en-us/dotnet/core/install/windows#supported-versions)

## Reproduction

Install QEMU, xorriso and OpenSSL on the developer machine. The [archived copy of the Microsoft evaluation disc](https://archive.org/details/Win7EntNEvalSP1) has SHA-256 `f3d9fbd1a0ce17ad6f9009f14155c392db131bb1b324a4da5e97e269b2b6a123`.

```sh
mise run test:win7 install /path/to/windows7-sp1-x64.iso
mise run release win-x64
mise exec -- node tests/win7/fixture.mjs
```

To run the self-contained JIT package on a fresh SP1 install, place x64 [KB3063858](https://download.microsoft.com/download/0/8/e/08e0386b-f6af-4651-8d1b-c0a95d2731f0/Windows6.1-KB3063858-x64.msu), [KB2999226](https://support.microsoft.com/help/2999226) and [VC++ 2015–2019](https://aka.ms/vs/16/release/vc_redist.x64.exe) in `artifacts/win7/fixture/updates/` under the names `loader.msu`, `ucrt.msu` and `vc_redist.x64.exe`. The guest installs them and reboots. The three packages were evaluated together. Their individual necessity has not been established.

Leave the temporary primary running and execute `mise run test:win7 run artifacts/win7/fixture` in another terminal. The serial log contains `LTH-TEST-PASS` on success and is also saved as `artifacts/win7/fixture-result.txt`. Restarting the fixture provisions a new account, certificate chain and workspace.

## Archived Native AOT evaluation

Git revision `0d058bb` preserves the standalone CLI, the Windows linker configuration and the native plugin probes under `.agents/prototypes/native-aot/`. With YY-Thunks and the static Universal CRT, the remote CLI passed the HTTPS reader scenario on original Win7 SP1. Independently compiled native hosts and libraries on macOS ARM64, Linux ARM64 and Win7 x64 shared a process, callbacks and a borrowed buffer. An isolated native macOS greeting endpoint returned HTTP 200 through gRPC JSON transcoding. The complete macOS host failed native compilation while resolving `Avalonia.Controls.TreeDataGrid`. The JIT delivery retains cold-start managed DLLs, including plugin-provided commands and Avalonia pages. The original SP1 result applies only to the historical native CLI.
