# CLI frontend and Windows 7 compatibility

English | [中文](2026-11-23-mvp-win7-cli.zh.md)

## Frontend boundaries

CLI and GUI are peer presentations of the same workspace. The host opens a local generic host for either frontend and loads the enabled plugins once. The selected workspace and principal determine the available business operations. Each frontend owns its navigation, input, output and presentation state. A GUI view choice or CLI output convention stays local to its renderer.

A plugin registers an operation group with `AddCapabilities<T>`. Public methods marked `[Capability]` define the action, typed arguments, defaults, result and cancellation. `LazyTuiHub.Interaction` reads those signatures for discovery and invocation. The games and reader pages use the typed operations directly. The CLI derives its help and dispatch from the catalog. The desktop generates a searchable form for every registered operation, including plugins without a dedicated page. Additional presentations can combine operations into a task without registering another business action. Local operations retain application and resource authorization. Only active plugins contribute executable groups. Saved declarations retain the ownership of unavailable groups.

The host accepts `--cli` and `--desktop`. With an HTTPS endpoint, both select the same remote catalog for sessions, feeds and articles and use the generated clients. The remote desktop can load its reader presentation independently of the server plugins and local database. The standalone CLI remains the smaller remote-only package. Workspace administration and games currently require the local host. Publishing an interactive capability does not create a network endpoint. Remote exposure follows the existing Proto and authorization process.

Run `mise run run:cli` to list groups, or `mise run run:cli -- games --help` to discover actions and inputs. On the desktop, choose **Find an operation** or press Command+K on macOS or Ctrl+K elsewhere. Commands accept secret input on stdin or from a masked terminal prompt. Desktop forms mask secrets. CLI results use stdout, with progress and diagnostics on stderr. Both entries support cancellation. A secured local workspace starts with sign-in until it obtains a user session. Set `Access__Session` to reuse an issued token in a later process and `Access__Account` to select a shared account.

## Guest and method

The reference guest is the English Microsoft Windows 7 Enterprise N SP1 x64 Evaluation release, build 7601.17514, with the i440FX machine, IDE disk and e1000 network adapter in QEMU. The unattended answer file installs only onto a newly created virtual disk. After setup, a startup task runs the test from its attached read-only CD and reports through the emulated serial port. Every functional test boots a new qcow2 overlay. Guest trust-store changes, package installations and test data are confined to that overlay.

The remote probe uses a real primary, a disposable account and an RSS fixture. It logs in over HTTPS, lists, creates, refreshes and reads a feed, lists articles by source, gets an article, marks it read and logs out. The local probe starts the host, loads the game DLL, writes to SQLite, then starts a second process and reads the same game. The [Win7 lab](../../tests/win7/) mounts the production host and CLI from the win-x64 release alongside the disposable fixture.

## Supported release and verified behavior

The [product release](../../docs/development/release.en.md) supplies the ordinary self-contained Windows x64 JIT host and CLI. The original Win7 SP1 loader cannot start these packages. On SP1 with KB3063858, KB2999226 and the VC++ 2015–2019 x64 redistributable, the CLI completed the remote reader scenario and the host loaded the game plugin, wrote SQLite and read back the data after restart. The tests installed all three prerequisites together and did not isolate their individual effects. Desktop windows, serving HTTP, distributed tasks and online game providers remain unverified on Win7. [Microsoft's supported Windows versions](https://learn.microsoft.com/en-us/dotnet/core/install/windows#supported-versions)

## Reproduction

Install QEMU, xorriso and OpenSSL on the developer machine. The [archived copy of the Microsoft evaluation disc](https://archive.org/details/Win7EntNEvalSP1) has SHA-256 `f3d9fbd1a0ce17ad6f9009f14155c392db131bb1b324a4da5e97e269b2b6a123`.

```sh
mise -E development run test:win7 install /path/to/windows7-sp1-x64.iso
mise -E production run release win-x64
mise exec -- node tests/win7/fixture.mjs
```

To run the self-contained JIT package on a fresh SP1 install, place x64 [KB3063858](https://download.microsoft.com/download/0/8/e/08e0386b-f6af-4651-8d1b-c0a95d2731f0/Windows6.1-KB3063858-x64.msu), [KB2999226](https://support.microsoft.com/help/2999226) and [VC++ 2015–2019](https://aka.ms/vs/16/release/vc_redist.x64.exe) in `.local/win7/fixture/updates/` under the names `loader.msu`, `ucrt.msu` and `vc_redist.x64.exe`. The guest installs them and reboots.

Leave the temporary primary running and execute `mise -E development run test:win7 run .local/win7/fixture` in another terminal. The serial log contains `LTH-TEST-PASS` on success and is also saved as `.local/win7/fixture-result.txt`. Restarting the fixture provisions a new account, certificate chain and workspace.

## Archived Native AOT evaluation

Git revision `0d058bb` preserves the standalone CLI, the Windows linker configuration and the native plugin probes under `.agents/prototypes/native-aot/`. With YY-Thunks and the static Universal CRT, the remote CLI passed the HTTPS reader scenario on original Win7 SP1. Independently compiled native hosts and libraries on macOS ARM64, Linux ARM64 and Win7 x64 shared a process, callbacks and a borrowed buffer. An isolated native macOS greeting endpoint returned HTTP 200 through gRPC JSON transcoding. The complete macOS host failed native compilation while resolving `Avalonia.Controls.TreeDataGrid`. The JIT delivery retains cold-start managed DLLs, including plugin-provided commands and Avalonia pages. The original SP1 result applies only to the historical native CLI.
