# MVP 游戏库与资料来源

[English](2026-11-23-mvp-games.en.md) | 中文

## 从已有产品带入的概念

librarian 的 Gebura 区分用户收藏的游戏、外部来源资料和商店条目，还记录分类与游玩时间。waiter 在客户端进一步区分游戏、设备上的安装实例和启动方式，支持扫描游戏目录、抓取资料和记录运行时间。本轮先引入能独立使用的游戏库与来源查询。安装实例、启动器、目录扫描、自动计时、私人平台账户与已购库同步，以及桌面交互，留给后续讨论。[librarian 游戏模型](https://github.com/tuihub/librarian/blob/1fcb0f342a9d35134139707446e426dd2972bb03/internal/model/modelgebura/modelgebura.go) · [waiter 游戏仓库](https://github.com/tuihub/waiter/blob/ae1ae6f349eef99a8a300ed9276c319683ef5797/lib/repo/gebura_repo.dart)

## 游戏、来源与关联

`games` 插件保存账户内的游戏 ID、用户标题、分类和按设备记录的游玩时段。手工建库无需启用任何 provider。Steam、Bangumi 和 VNDB 各自注册可独立启停的插件，提供按名称搜索和按来源 ID 读取详情的节点。在线搜索返回上游首页候选。各来源保留原始 ID，已导入的资料和游戏关联在 provider 缺失期间仍可查看。[插件边界](2026-11-17-mvp-plugins.zh.md)

导入工作流先取得来源资料，再交给拥有主工作区资源的节点写入。资料查询可以在其他具有对应插件的实例上执行。指定目标游戏即确认一条关联。同一游戏可以收录多个来源，同一来源条目也可以描述多个游戏。省略目标时，首次导入会建游戏，后续导入会刷新唯一关联；有多个目标时须指定其中一个。刷新保留用户标题、分类和游玩时段。工作区在同一事务中保存来源快照和框架的 `describes` 关系。游戏库按账户和游戏 URI 检查读写权限。[账户与资源权限](2026-11-19-mvp-account-identity.zh.md)

## 三个数据仓库的作用

| 来源 | 可用入口 | 在 MVP 中的用途 |
| - | - | - |
| [tuihub/bangumi-db](https://github.com/tuihub/bangumi-db) | PostgreSQL 的 `public.subject` | [导出脚本](../../src/LazyTuiHub.Bangumi/export-games.sql)选取游戏条目，保留原名、中文名、简介和日期。 |
| [tuihub/vndb-db](https://github.com/tuihub/vndb-db) | VNDB 数据库的 `vn_titles` | [导出脚本](../../src/LazyTuiHub.Vndb/export-games.sql)按 VNDB ID 选取一个标题，优先日文、其次英文，同时保留该行的拉丁转写。在线详情可另取简介、图片和开发者。 |
| [tuihub/tuihub-datasets](https://github.com/tuihub/tuihub-datasets) | 发布的 [vndb_id_connector.json](https://datasets.tuihub.org/vndb_id_connector.json) 和 [game_id_list.json](https://datasets.tuihub.org/game_id_list.json) | `games matches` 按提供方及原始 ID 返回所有匹配行，保留别名、多个候选及单行内的多个 ID。用户可据此选择要关联的来源。 |

每个 provider 默认查询公开服务。Steam 商店默认使用美国区和英文，可通过 `Games:steam:Country` 和 `Games:steam:Language` 选择其他地区和语言。Steam 详情保留商店条目的类型，可区分本体、试玩版和 DLC。[Steam 商店详情示例](https://store.steampowered.com/api/appdetails?appids=620) · [Bangumi API](https://github.com/bangumi/api) · [VNDB API](https://api.vndb.org/kana)

在执行查询的实例上也可为单个 provider 配置本地 JSONL 快照。两个 PostgreSQL 导出脚本可通过 `psql -XAt -v ON_ERROR_STOP=1 -f` 生成这种快照。应用逐行读取文件，以主键查详情，以标题或别名搜索。跨站对照表由 CLI 按需读取，查询本身不改动游戏库。部署者决定何时更新快照及对照表。

## 运行示例

```sh
mise run run -- --command games --action add --title "我的 CLANNAD"
mise run run -- --command bangumi --action search --query CLANNAD
mise run run -- --command bangumi --action import --source-id 13 --game GAME_ID
mise run run -- --command games --action matches --dataset ./game_id_list.json --provider bangumi --source-id 13
mise run run -- --command vndb --action lookup --source-id v4 --Games:vndb:Snapshot ./vndb.jsonl
mise run run -- --command games --action show --game GAME_ID
```

`GAME_ID` 取第一条命令返回的 ID。各命令默认使用同一个本地工作区，可用 `--database PATH` 选择其他工作区。
