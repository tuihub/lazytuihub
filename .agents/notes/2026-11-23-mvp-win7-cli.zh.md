# CLI 前端与 Windows 7 兼容性

[English](2026-11-23-mvp-win7-cli.en.md) | 中文

## 前端边界

CLI 与 GUI 是同一工作区的平级入口。两者在本地均创建通用宿主并冷启动已启用的插件。工作区和当前身份决定可调用的业务能力。两个前端分别安排导航、输入、输出和呈现状态。GUI 的视图选择与 CLI 的输出格式各自由前端管理。

插件通过 `AddCapabilities<T>` 注册操作组。带 `[Capability]` 的公开方法声明动作、类型化参数、默认值、结果与取消信号。`LazyTuiHub.Interaction` 根据方法签名发现并调用操作。游戏库和阅读器页面直接调用相同的类型化操作。CLI 根据目录显示帮助和分派命令。桌面根据目录生成可搜索的表单，未提供专属页面的插件也能直接使用。专属界面可以组合多个操作完成一项任务。业务与资源权限仍由应用服务执行。只有已激活的插件提供可执行操作，保存的声明继续记录缺失操作组的所属插件。

宿主分别接受 `--cli` 和 `--desktop`。指定 HTTPS 端点后，两者都使用远程会话、订阅和文章能力目录，并通过生成的客户端调用服务。远程桌面可单独加载阅读器界面，无需本地服务端插件和数据库。独立 CLI 继续作为轻量远程发布包。游戏和工作区管理目前需要本地宿主。交互能力的注册只影响前端。远程开放能力沿用 Proto 与权限设计流程。

运行 `mise run run:cli` 列出操作组，运行 `mise run run:cli -- games --help` 查看游戏操作和参数。在桌面选择 **Find an operation**，也可在 macOS 按 Command+K，其他系统按 Ctrl+K。CLI 通过标准输入或隐藏回显的提示读取密钥，桌面表单遮盖密钥。CLI 将结果写入标准输出，将进度和诊断写入标准错误。两个入口都支持取消。启用身份校验的本地工作区先登录，再开放业务能力。后续进程通过 `Access__Session` 使用已签发的令牌，通过 `Access__Account` 选择共享账户。

## 来宾与验证方法

基线选用微软英文 Windows 7 Enterprise N SP1 x64 Evaluation，构建号 7601.17514。QEMU 提供 i440FX 机型、IDE 磁盘和 e1000 网卡。无人值守安装只操作实验新建的虚拟盘。安装结束后，开机任务从只读光盘运行测试，通过模拟串口返回结果。每次功能测试均从新的 qcow2 差分盘启动，来宾证书、系统补丁和业务数据只写入该层。

远程测试使用真实主节点、临时账户和 RSS 测试源。CLI 通过 HTTPS 登录，列出、新建、刷新和读取订阅，按来源列出文章，读取文章、标为已读并注销。本地测试通过宿主冷启动加载游戏插件 DLL，写入 SQLite，再启动第二个进程读回同一条记录。[Win7 实验工具](../../tests/win7/)将正式 win-x64 发布包中的宿主和 CLI 与临时夹具一起挂入来宾。

## 正式交付与验证范围

[产品发布](../../docs/development/release.zh.md)提供常规的 Windows x64 自包含 JIT 宿主及 CLI。原版 Win7 SP1 的加载器无法启动这两个包。安装 KB3063858、KB2999226 和 VC++ 2015–2019 x64 运行库后，CLI 完成远程阅读流程，宿主加载游戏插件，写入 SQLite 并在重启后读回。三个依赖作为一组验证。Win7 上的桌面窗口、HTTP 监听、分布式任务和在线游戏提供方尚待验证。[微软支持的 Windows 版本](https://learn.microsoft.com/en-us/dotnet/core/install/windows#supported-versions)

## 复现

开发机需要 QEMU、xorriso 和 OpenSSL。安装盘来自[微软评估介质的归档副本](https://archive.org/details/Win7EntNEvalSP1)，整盘 SHA-256 为 `f3d9fbd1a0ce17ad6f9009f14155c392db131bb1b324a4da5e97e269b2b6a123`。

```sh
mise run test:win7 install /path/to/windows7-sp1-x64.iso
mise run release win-x64
mise exec -- node tests/win7/fixture.mjs
```

要在原版 SP1 上运行自包含 JIT 包，请在 `.local/win7/fixture/updates/` 放入 x64 的 [KB3063858](https://download.microsoft.com/download/0/8/e/08e0386b-f6af-4651-8d1b-c0a95d2731f0/Windows6.1-KB3063858-x64.msu)、[KB2999226](https://support.microsoft.com/help/2999226) 和 [VC++ 2015–2019](https://aka.ms/vs/16/release/vc_redist.x64.exe)，分别命名为 `loader.msu`、`ucrt.msu`、`vc_redist.x64.exe`。来宾自动安装并重启。三个包作为一组验证，尚未逐个确定最小组合。

保持临时主节点运行，在第二个终端执行 `mise run test:win7 run .local/win7/fixture`。成功时串口输出 `LTH-TEST-PASS`，完整记录写在 `.local/win7/fixture-result.txt`。停止临时主节点后，下次运行会重新生成账户、证书和工作区。

## Native AOT 实验记录

Git 修订 `0d058bb` 保留独立 CLI、Windows 原生链接配置及 `.agents/prototypes/native-aot/` 下的原生插件样例。当时借助 YY-Thunks 与静态 Universal CRT，远程 CLI 在原版 Win7 SP1 上通过 HTTPS 阅读流程。分别编译的原生宿主与动态库在 macOS ARM64、Linux ARM64 和 Win7 x64 上验证了同进程调用、回调和借用缓冲区。隔离的 macOS 原生问候端点通过 gRPC JSON 转码返回 HTTP 200。完整 macOS 宿主在原生编译时无法解析 `Avalonia.Controls.TreeDataGrid`。正式交付选择 JIT，以保留冷启动加载托管 DLL、插件命令和 Avalonia 页面等能力。原版 SP1 的成功记录仅适用于历史原生 CLI。
