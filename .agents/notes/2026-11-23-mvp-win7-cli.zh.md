# CLI 前端与 Windows 7 兼容性

[English](2026-11-23-mvp-win7-cli.en.md) | 中文

## 前端边界

宿主通过 `--cli` 启动本地命令行，通过 `--desktop` 启动桌面。本地阅读命令在进程内调用文章和订阅 API。工作区、游戏与插件命令沿用原有账户权限，直接调用本地服务。独立 CLI 通过生成的客户端连接 HTTPS 服务，可以登录、选择共享账户、管理订阅、列出和读取文章、标为已读以及撤销会话。它的发布包包含 API 类型和 HTTP 客户端；SQLite、HTTP 服务端、业务插件和 Avalonia 随宿主发布。

运行 `mise run run:cli -- --command articles --action list` 可以在本地阅读。传入 `--endpoint https://SERVER` 可切换到远程服务。使用 `--command access --action login --username USER` 获取会话令牌，后续命令通过 `Access__Session` 使用令牌。远程客户端保留证书、吊销状态和访问权限检查。

## 来宾与验证方法

基线选用微软英文 Windows 7 Enterprise N SP1 x64 Evaluation，构建号 7601.17514。QEMU 提供 i440FX 机型、IDE 磁盘和 e1000 网卡。无人值守安装只操作实验新建的虚拟盘。安装结束后，开机任务从只读光盘运行测试，通过模拟串口返回结果。每次功能测试均从新的 qcow2 差分盘启动，来宾证书、系统补丁和业务数据只写入该层。

远程测试使用真实主节点、临时账户和 RSS 测试源。CLI 通过 HTTPS 登录，列出、新建、刷新和读取订阅，按来源列出文章，读取文章、标为已读并注销。本地测试通过宿主冷启动加载游戏插件 DLL，写入 SQLite，再启动第二个进程读回同一条记录。[Win7 实验工具](../../tests/win7/)对两种发布包均执行远程测试，并对 JIT 宿主执行本地测试。

## 发布方式与功能实测

两种发布方式均采用[仓库 LTS 基线](2026-11-24-dotnet-lts.zh.md)。QEMU 在 Apple Silicon 上运行 x64 来宾。测试主节点使用相同的应用运行时，两端保留 HTTPS、证书吊销和账户权限校验。

| 发布方式 | Windows 7 SP1 x64 环境 | 验证范围 |
| --- | --- | --- |
| 独立 Native AOT CLI | 原版 SP1，导入临时测试 CA | 远程订阅与文章操作，包括登录和注销 |
| 自包含 JIT CLI 与本地宿主 | SP1 安装 KB3063858、KB2999226 和 VC++ 2015–2019 x64 运行库 | 远程操作，冷启动加载游戏插件 DLL，写入 SQLite 后在新进程中读回 |

原版 SP1 的加载器无法启动普通自包含 JIT 包。表中的三个依赖作为一组验证。只使用远程阅读功能时，可以部署一个 Native AOT 可执行文件。发布时链接 YY-Thunks 1.2.3 和微软静态 Universal CRT。在 macOS 上，微软 Native AOT 编译器配合 Windows SDK、CRT 库和 LLVM 的 `lld-link` 生成 x64 可执行文件。跨操作系统编译超出微软的 Native AOT 官方支持范围。[YY-Thunks](https://github.com/Chuyu-Team/YY-Thunks) · [xwin](https://github.com/Jake-Shadle/xwin) · [微软交叉编译说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/cross-compile)

API 生成器提供具体的 Protobuf JSON 转换器，CLI 通过源生成的元数据输出登录结果。NSwag 和 Google.Protobuf 仍有裁剪及 AOT 警告。更新运行时或依赖、调整原生链接方式或改变 API 数据类型后，需要在来宾中复验。本地宿主使用 JIT，以便冷启动时加载托管 DLL。微软的支持矩阵未包含 Win7。此来宾尚未验证桌面窗口、HTTP 监听、分布式任务和在线游戏数据提供方。[Native AOT 限制](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/#limitations-of-native-aot-deployment) · [微软支持矩阵](https://learn.microsoft.com/en-us/dotnet/core/install/windows#supported-versions)

## 复现

开发机需要 QEMU、xorriso 和 OpenSSL。安装盘来自[微软评估介质的归档副本](https://archive.org/details/Win7EntNEvalSP1)，整盘 SHA-256 为 `f3d9fbd1a0ce17ad6f9009f14155c392db131bb1b324a4da5e97e269b2b6a123`。

```sh
mise run test:win7 install /path/to/windows7-sp1-x64.iso
mise run test:win7:publish
mise exec -- node tests/win7/fixture.mjs
```

要在原版 SP1 上运行自包含 JIT 包，请在 `artifacts/win7/jit/updates/` 放入 x64 的 [KB3063858](https://download.microsoft.com/download/0/8/e/08e0386b-f6af-4651-8d1b-c0a95d2731f0/Windows6.1-KB3063858-x64.msu)、[KB2999226](https://support.microsoft.com/help/2999226) 和 [VC++ 2015–2019](https://aka.ms/vs/16/release/vc_redist.x64.exe)，分别命名为 `loader.msu`、`ucrt.msu`、`vc_redist.x64.exe`。来宾自动安装并重启。三个包作为一组验证，尚未逐个确定最小组合。

保持临时主节点运行，在第二个终端执行 `mise run test:win7 run artifacts/win7/jit`。成功时串口输出 `LTH-TEST-PASS`，完整记录写在 `artifacts/win7/jit-result.txt`。停止临时主节点后，下次运行会重新生成账户、证书和工作区。

在 macOS 上构建独立 AOT 版需要 xwin 和 LLVM lld，并确保能从 PATH 运行 `lld-link`。确认微软 SDK 许可后，准备 SDK 并启动同一套测试服务。

```sh
xwin --accept-license --arch x86_64 --cache-dir artifacts/win7/xwin-cache splat --preserve-ms-arch-notation --disable-symlinks --output artifacts/win7/windows-sdk
mise run test:win7:publish:aot
mise exec -- dotnet build src/LazyTuiHub -c Release
mise exec -- node tests/win7/fixture.mjs artifacts/win7/aot
```

在另一终端运行 `mise run test:win7 run artifacts/win7/aot`，即可用原版 SP1 验证。可执行文件位于 `artifacts/win7/aot/cli/LazyTuiHub.Cli.exe`，来宾串口记录位于 `artifacts/win7/aot-result.txt`。
